---
name: woori-api-change
description: 공개 API와 DTO 또는 오류 응답 변경 시 서버와 클라이언트 호환성을 확인한다.
---

1. 서버 OpenAPI와 실제 controller/DTO, 클라이언트 서비스 호출을 확인한다.
2. 요청/응답/오류/인증 조건의 변화 및 이전 소비자 동작을 표로 비교한다.
3. 요청받은 범위의 구현과 명세를 함께 수정하고 성공·입력 오류·권한 거부를 검증한다.
4. 다른 저장소 변경이 필요하면 범위와 소비자 영향부터 확인한다. 저장소 간 직접 import는 하지 않는다.
5. 파괴적 변경은 확장 → 서버 배포 → 소비자 전환 → 구 형식 제거의 호환 순서를 검토한다.
6. 새 서버 계약 버전(info.version X.Y.Z)에서 처음 생긴 API를 쓰기 시작하면 같은 PR에서 scripts/api-contract.mjs의 최소 버전을 X.Y.Z로 올린다(운영 배포 게이트, 내리지 않는다).

출처: harness-engineer. 원본 절차를 프로젝트에 맞게 재작성했으며 프레임워크 구조/명명 규칙은 가져오지 않았다.
